# Mateo Fit 0.11.1（22）：后台执行与输入框修复

交付日期：2026-11-05。后台能力在 0.11.0（21）上线，用户已确认切到其他 App 后返回能恢复进度或看到完整回复。随后用户报告“点击发送后就没清空”，0.11.1（22）补上输入控件生命周期保护，已覆盖安装、读回版本并启动；用户随后确认“立即清空，新草稿也保留”，本次输入修复真机验收通过。

## 当前行为

- 提交成功后，问题由私人服务器继续处理。切后台、切换对话、手机进程退出都不会主动取消已受理任务。
- 返回 App 后，按原请求 ID 查询并恢复到原对话；已有新草稿保留。后台餐食分析回到所属对话的待确认草稿，不直接计入吃过的记录。
- 点停止或清空该对话会产生持久的取消请求。离线时取消在下次连接后送达；迟到结果不再采用。切换、归档对话不等于取消。
- 服务器执行已有 Thinking／联网研究流程，保留约 300 秒执行上限。用户于 2026-11-05 要求取消应用每日与每分钟调用次数配额，已部署并验证；用量统计保留。最多四个排队或运行任务、两个并行生成，排队超过十分钟失败。它不是无限运行的自主 Agent。
- 免费 Personal Team 暂无原生远程通知配置。用户明确选择先完成后台执行，本版没有系统完成通知，也没有用定时本地通知冒充完成提醒。

## 输入框修复与证据边界

已在事件重放中复现：发送接受后，逻辑草稿先清空；旧文本控件随后回写发送前内容，会恢复到输入框并被延迟保存。这说明旧绑定缺少生命周期隔离，但不将事件重放声称为已捕获手机内部输入法回调。

修复给每次输入控件生命周期分配修订号。发送成功和切换恢复草稿时退休旧绑定；旧回调无法写进下一份草稿。发送成功后重建原生文本控件，使其显示清空后的内容。普通按键不重建控件，仍只由输入区观察，不扫描历史、不发起模型请求。拒绝发送保留原文和当前编辑状态。

新增十项检查覆盖原错误路径、迟到事件、真正的新草稿、后台保存、会话恢复、发送失败、继续编辑、每次输入的通知数量，以及一百次重复发送／旧事件回写。旧绑定测试按预期失败，新绑定全部通过。原有 23 项聊天检查继续通过。

模拟器原生输入工具出现 ScreenCaptureKit -3811/-3812 错误，无法稳定完成真实键盘发送验证；已保留此自动化限制。用户随后在 0.11.1 真机确认“立即清空，新草稿也保留”；真机通过依据是用户反馈，而非编译或事件重放。

## 协议与隐私

新增接口保持旧客户端兼容：

| 接口 | 行为 |
| --- | --- |
| `POST /agent/jobs` | 接收 device_id、thread_id、kind、完整原请求；原请求 ID 为幂等键。同键同内容返回既有状态；冲突拒绝 |
| `GET /agent/jobs/{id}` | 鉴权后读取状态、阶段、有限预览、已验证结果；轮询不计模型请求额度 |
| `DELETE /agent/jobs/{id}` | 取消并清除内容；即使取消先于迟到 POST 到达，也以取消墓碑阻止重新生成 |
| `POST /agent/jobs/{id}/ack` | App 原子保存结果后确认取回，服务器清除输入、预览及结果 |
| `POST /agent/status` | 新增 background_jobs、job_retention_hours、completion_notifications；旧接口保留 |

任务正文、预览和结果使用 Fernet 认证加密存入 SQLite；独立随机密钥文件和数据库权限为 0600，服务状态目录 0700。服务端需要在处理时解密，不将此称为端到端加密。结果取回并在本机保存后删除，未取回最多保留 24 小时；无内容的幂等墓碑最多再保留 24 小时。服务重启将运行中任务标为失败，不自动重复付费调用；排队任务可继续。

App 的本地任务不含连接令牌，只保存令牌摘要用于绑定原连接；更换地址或凭据不会把旧健康请求上传到新服务。摘要授权撤销、相关记忆更正／忘记、关闭会话记忆学习会使相关任务停止采用。旧快照的回复可读，但过期操作不重新获得执行资格。备份恢复会停止其中的旧任务，不自动重新上传。

当前设置说明已更新暂存范围。本轮没有上传用户真实健康记录；真实 API 和模拟器使用软件主题合成消息。供应商副本仍适用原有供应商政策，不声称删除本地记录或私人服务结果等于删除供应商副本。

部署采用 `/var/lib/mateo-fit-agent/jobs.sqlite3` 和同目录 `jobs.key`，不进入源码归档或代码部署包。Docker 继续使用持久的 `/data` 卷。依赖新增 cryptography 50.0.2，锁文件同步；旧客户端的流式路径行为保留。
