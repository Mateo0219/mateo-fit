# Mateo Fit：个人身体健康与减脂健身 Agent 产品梳理

> 0.9.0 更新：第一批“可管理记忆 + 聊天内执行”已实现、部署并覆盖安装，详见 [交付说明](personal-agent-v090.md)。以下保留最初 0.8.3 调研基线；其中关于记忆和操作尚未实现的描述属于历史状态。长期目标、后台任务和主动提醒仍待开发。

调研日期：2026-11-04。依据当前 0.8.3 源码、用户反馈、OpenAI Dots 与 Meta Muse 官方产品/设计/控制说明。产品资料研究不等于实际账号体验测试。下文是产品建议，尚未实现的能力不计入当前交付。

**产品定位**

Mateo Fit 是持续服务同一个人的身体健康、饮食、训练与恢复 Agent：理解长期目标和生活条件，读取已授权的最新事实，把需求落实为可执行、可记录、可更正的行动，并在适当时机跟进。首页继续保持简洁聊天，复杂性由系统承担。

**从 Dots、Muse 学什么**

| 官方可核实的设计 | 对 Mateo Fit 的产品启发 |
|---|---|
| Dots 有持续上下文、定时任务、后台主动研究与自定义行动规则；主动研究有只读限制。[官方介绍](https://openai.com/index/introducing-dots/) | 已授权数据更新后先形成观察和候选建议，实际记录和计划修改经过受控事务；给用户暂停跟进的入口。 |
| Muse 采用主聊天、分支聊天、跨会话记忆、目标视图、后台活动和可编辑的记忆文件。[官方设计说明](https://introducing.muse.ai/) | 新对话和换模型继续服务同一个人；目标、记忆和活动可以查看，但不占据空白聊天首页。 |
| Muse 强调只有新结果或需要用户判断时才通知，并为关键操作保留明确控件。[官方设计说明](https://introducing.muse.ai/) | 提醒以帮助做决定为目的；一次有意义的确认代替多层表单，能暂停、延后和调整频率。 |
| Dots 当前不能逐条直接查看、修改或删除它自己的记忆；停用记忆共享、断开插件也不清除已获取的上下文。[官方控制说明](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs) | 健康 Agent 应从第一版提供逐条纠错、失效、删除与来源追踪，明确聊天、记忆、正式记录和备份的不同删除范围。 |
| Muse 的权限、凭据和持久状态与模型运行环境分离。[官方工程说明](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) | 复用 App 的确定性计算、版本检查、幂等保存与撤销；模型理解需求和提出操作，App 控制提交。 |

上述“官方能力”与右栏“设计建议”分开理解。当前资料不能证明这些通用 Agent 的健康建议经过临床验证，也不能证明“专属云电脑”代表服务商无法访问数据；不将此类表述引入产品承诺。

**当前基础与差距**

已有：文字/照片聊天、多会话与草稿恢复、模型切换、结构化个人档案、训练与饮食记录、体重睡眠分析、必要摘要授权、部分确认事务、餐食核对保存、版本与重复提交防护。

关键差距：

- `Sources/FitnessCore/CoachAssistant.swift:153` 仅选当前会话最近四轮完整回复，并按授权过滤。正式记录摘要是独立通道；保存聊天不等于建立完整长期记忆。
- `Server/assistant_coach.py:54` 仍主要解释快照、选有限候选、引导打开模块。尚无覆盖日常自然语言记录、更正和动作替代的完整事务集合。
- `Sources/FitnessApp/CoachHomeView.swift:110` 进入后台会停止当前请求；已有的是请求恢复，不是关掉 App 后继续推进长期任务。
- 没有通用记忆管理、目标生命周期、可暂停的主动跟进、对建议实际效果的持续学习闭环。

**Memory 要分开保存的六类信息**

| 类型 | 内容举例（仅示例） | 生命周期与使用方式 |
|---|---|---|
| 稳定资料与偏好 | 已确认的限制、可用器械、饮食偏好、希望回复简短 | 跨会话使用；保留来源与最后确认时间。限制不能凭推断解除。 |
| 长期目标与约束 | 当前减脂/力量目标、可投入时间、阶段重点 | 可修改、暂停和结束；目标体重不能写成实测体重。 |
| 当天或阶段状态 | 今天可训练时间、出差日期、主观疲劳 | 保存作用日期；到期变为未知或不适用，不能自动当作恢复正常。 |
| 正式事实与记录 | 实测体重、实际完成组数、确认过的餐食 | 结构化原始记录是依据；按日期和来源查询，摘要不能覆盖原记录。 |
| 未完成事项 | 待补餐食份量、未结束训练、待确认调整 | 有状态、所属任务与下一步；完成后关闭，不能反复催促。 |
| 策略与反馈 | 用户明确反馈某类安排更容易执行 | 区分观察与假设，保留样本和时间；不能把缺记录推断为不自律。 |

记忆需要支持这些具体交互：

- 自然说“记住我通常……”即可提出记忆；普通表达偏好可用“已记住 · 撤销”的轻反馈，健康限制、含糊推断或冲突事实需要核对。
- 能问“你记住了我什么”“这条依据哪里”“这点已经变了”“只在今天适用”“忘掉这条”。
- 每条至少包含内容、来源、记录/有效时间、确认状态和最近修订。内部推断不能伪装成用户确认。
- 新事实与旧事实矛盾时，标出冲突并问一句；不静默覆盖重要限制。
- 删除某条记忆后，同步失效相关摘要和检索索引，防止从旧总结自动重新生成。历史原文是否保留应可单独选择。
- 临时聊天可选择不形成长期记忆；清空聊天、忘记偏好、删除正式日志各有明确范围。
- 记忆属于用户而非模型。换 Flash / Pro 或新建会话，长期资料、目标与正式记录保持一致。
- 每次只检索当前任务相关、仍有效且已授权的信息；不把全部历史塞进每次请求。

**值得补齐的功能与优先级**

| 优先级 | 能力 | 用户能感受到的结果 |
|---|---|---|
| 第一批 | 可管理的长期记忆与按任务取用 | 少重复自我介绍；能够纠正 Agent 的理解；换对话仍然了解同一个人。 |
| 第一批 | 聊天内更新当天条件 | “今天只有四十分钟”可形成当天调整，继续当前训练任务，不要求重填档案。 |
| 第一批 | 自然语言记录与更正 | 明确说做了什么或吃了什么，展示待保存事实，一次核对后落库；“刚才重量写错了”能定位原记录。 |
| 第一批 | 工具执行及结果读回 | 回答清楚“提出了什么、保存了什么、哪里未完成”，重试不重复记录，已有组数保留。 |
| 第二批 | 目标、计划和任务续接 | 目标有阶段、当前计划、下一步、暂停/结束状态；计划生成不等于用户执行完成。 |
| 第二批 | 任务状态与活动记录 | 可看正在处理、等用户、已完成、失败；关掉 App 后再回来能接续，有一键停止。 |
| 第二批 | 建议效果反馈 | 接受、修改、没采用及原因回到下一次安排；优先改善可执行性，避免无证据频繁换计划。 |
| 第三批 | 受控的主动跟进 | 按用户选定时间或相关数据变化触发，默认少打扰；提醒能延后、暂停、关闭。 |
| 第三批 | 简短周复盘与计划差异 | 显示记录覆盖、实际变化、保留项与拟修改项；修改确认后可追溯、可撤销。 |
| 按使用反馈补充 | 语音、相机直拍、真实流式、训练中快捷操作 | 减少训练时输入；先核对识别出的重量/次数/份量，保持已有停止和草稿恢复行为。 |

**把“能执行”拆成可检查的工具**

第一组只读能力应能查询最新健康摘要、当前训练及已完成组数、指定日期的记录、有效记忆与未完事项。第二组事务应覆盖更新当天条件、记录/更正训练、记录/更正餐食、替代待做动作、提出并确认计划变化、撤销自己的上一次修改。

模型负责理解、选择和解释；App 负责单位换算、营养汇总、计划约束、版本与幂等检查、最终提交和读回。先把这些受控能力接完整，再评估通用电脑控制、复杂插件或多 Agent。现有健身技能文件可继续作为四类工作流：训练、饮食、身体分析、复盘；技能有知识来源、版本和适用条件，并不等于工具已经实现。

**主动性应该怎样工作**

首次在设置中选定可读取的数据范围、主动程度、时段与频率，不反复出现“允许本次对话”。日常只读整理可在已授权范围内完成；改变训练计划、确认食物吃过、改正式记录仍需清楚的提交动作。

合适的触发例子是完成训练后整理本次表现、约定时段提醒尚未处理的餐食草稿、到复盘日准备一份有覆盖说明的报告。数据没同步与“没有发生”必须区分；已知来源未更新时标注最后可用时间。

健康记录留在手机的设计需要继续保留。关 App 后完成复杂任务，需新增持久任务、可取消的服务端执行及通知，只发送已授权的必要摘要。iOS 后台运行与 HealthKit 数据到达不保证精确时刻，产品不能假装拥有持续实时数据。先用新事件或指定时段触发，避免全天循环调用模型。

**界面应继续克制**

保留当前聊天首页和历史。记忆、目标、活动放在按需展开的入口中；不把它们变成常驻首页的多张卡片。回复默认先给当前结论与下一步，依据折叠。重要修改展示简短前后差异；普通读取无需审批。提醒直接打开对应任务，用户说“这周别催我”后应在可见的设置中体现暂停状态。

**一条完整体验示例（非用户真实记录）**

用户说自己通常周一、三、五晚上训练 → 系统形成可纠正的长期偏好；另一段会话说今天只有四十分钟 → 读取当前计划和已确认条件，提出适用的当天调整；训练中说某台器械被占 → 只调整剩余动作、保留已完成组数；结束时补充实际表现 → 核对后保存并返回真实结果；周末按约定复盘 → 区分实际完成、缺记录和推测，提出少量有依据的变化。

这个过程中，新对话或换模型不要求重新交代背景，短期状态不会污染长期偏好，提醒可以关闭。

**下一版建议的验收门槛**

1. 新对话中使用已经确认的偏好，能展示来源；修改后后续建议使用新版本。
2. “今天很累”不会改成长久偏好，过期后不作为当前事实；健康限制不会自动推断解除。
3. “我想练”不产生完成记录；一条实际训练或餐食通过核对只保存一次，能更正。
4. 新对话、换模型、退出再进入后，目标与待办仍可接续；任务状态与真实结果一致。
5. 暂停主动跟进后不继续提醒；缺数据时不伪造最新健康状态。
6. 忘记某条内容后，相关衍生摘要和检索结果不继续使用它。

首轮试用应关注重复询问次数、完成一条记录所需操作、纠错成本、错误记忆与重复写入、提醒是否有用。减脂结果与医疗效果不作为软件自动检查已经达成的证据。

建议开发顺序：**记忆与对话内事务 → 目标和任务续接 → 有节制的主动跟进与反馈复盘**。这是本次调研建议，需在下一轮明确实施范围后再开发。
