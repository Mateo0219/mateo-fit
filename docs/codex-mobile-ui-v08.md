2026-11-04。用户要求先研究 Codex 手机端 UI/UX，再把原生 App 前端做成“Codex 健身版”。

- [OpenAI：Work with Codex from anywhere](https://openai.com/index/work-with-codex-from-anywhere/)，确认手机端以会话、操作确认和结果审阅为主要工作方式。
- [OpenAI 帮助中心：ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)，确认 Codex 移动体验包含 ChatGPT App 内的 Remote／Codex Cloud；不将第三方同名 App 当作官方界面。

参考截图是官方发布时的界面，不声称复刻所有账号今天可见的逐像素版本。品牌仍为 Mateo Fit，模型信息来自实际配置。

## 设计对应

| 参考观察 | 本版实现 |
|---|---|
| 白底、黑灰文字、大留白和简洁图标 | 原生字体、白底、细分隔线、轻量描边卡片，统一模块配色 |
| Projects 与 Recents 的列表结构 | 训练、饮食、身体、复盘四个模块；下方是真实最近对话 |
| 顶部导航与独立会话 | 侧栏、搜索、新建、置顶、重命名、归档与恢复 |
| 大圆角输入框，上方文字、下方工具 | 附件、数据范围、实际模型信息、发送或停止；适配系统键盘 |
| 对话内呈现操作与结果 | 提案显示待确认状态，实际提交后显示保存结果；详细依据按需展开 |
| 快捷命令减少导航 | `/训练`、`/饮食`、`/身体`、`/复盘` 打开对应本地模块 |

没有加入不可用的语音按钮、假流式输出、模拟工具进度或虚构的模型选项。照片仍走系统相册，上传范围与写入确认沿用既有规则。

## 会话与数据

旧消息保留原 ID，迁入第一段对话。新会话使用独立历史；切换时保存各自未发送文字、照片和待确认餐食。置顶、改名和归档只整理聊天，不改变身体记录或训练计划。归档可恢复；清空仅影响选中的对话。完整备份覆盖会话及其草稿，校验所属会话、重复草稿和总照片大小。

模型没有新增写入能力。提案继续检查当前数据与计划版本；聊天列表变化不会使健康快照自动失效。跨对话仍保留已有不适暂停检查。切换对话会取消当前等待并结束会话授权；已发送的供应商请求不能被撤回。

本轮后端协议和模型保持现有配置。构建、检查、界面与真机交付的最终状态见 [validation-status.json](../validation-status.json) 和 [README](../README.md)。
