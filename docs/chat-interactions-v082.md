# Mateo Fit 0.8.2（15）：发送细节与模型切换

2026-11-04。根据“发送后文字仍在输入框”“全局检查此类细节”和“底部自行切换模型”的反馈完成。0.8.1 的输入流畅度已由用户回复“已经顺畅”确认；本版新增操作的真机反馈单独记录。

## 使用结果

- 输入区下方可选 **DeepSeek V4.1 Flash (1017)（图文）** 或 **DeepSeek V4 Pro (0813)（文字）**，选择会记住。列表来自已鉴权服务端；已向当前供应商账号核对两个模型可用，实际请求携带所选模型，后端再次校验白名单与图片能力。
- 每次发送先把文字和照片保存为待处理消息，然后立即清空输入框。等待回复时可以继续输入下一条；上一条回复、失败或停止都不会清掉新草稿。
- 失败与停止状态留在原消息下，可手动重试或编辑。重试复用原消息，每次尝试使用独立请求 ID；旧回复、重复回调和停止后的迟到回复不会执行。没有自动重试。
- 切换对话、后台、重启、首次解锁后恢复读取、备份恢复均保留草稿；失去处理进程的请求变为可重试状态，不一直转圈。
- 选照片时显示读取状态，读完前不发送；不支持图片的模型会提示切换，原输入与照片保留。
- 餐食分析仅生成待确认草稿。确认后更新原消息并显示实际保存结果，不重复生成用户消息；放弃后显示没有计入记录。过期草稿 ID 不能删除新的草稿。
- 复制回复有成功反馈，并包含回复中的补充问题与说明。可展开更早消息；阅读历史时，新回复不会强制拉回底部。
- 断网后可以通过底部模型菜单重新连接。切换模型影响下一次发送，正在进行的请求保留原模型标记。

首页保持空白聊天居中显示 Mateo Fit，历史和设置位于侧栏。健康摘要沿用单独、默认关闭的设置；模型选择不会扩大上传范围。原 App 标识 `com.personal.xuxu.app` 和数据目录沿用，覆盖安装，没有卸载。
