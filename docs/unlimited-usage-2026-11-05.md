# 取消应用调用次数配额

2026-11-05，用户明确要求“不要给我开限制”。本次只更新后端和部署配置；iPhone 继续使用已验收的 0.11.1（22），无需重装。

已取消应用自设的每日消息请求数、每日模型／搜索／网页读取调用次数，以及每分钟请求次数上限。不是清零当日计数，也不是把上限调成一个更大的数字。

三个配置均使用 `-1` 表示不设限，代码默认也不设限：`XUXU_MAX_DAILY_REQUESTS`、`XUXU_MAX_DAILY_PROVIDER_CALLS`、`XUXU_MAX_MINUTE_REQUESTS`。systemd 用户策略覆盖文件和 Docker／systemd 安装模板均同步，避免重启或部署后恢复旧的 100 次／天、10 次／分钟上限。工程约定记录了用户要求，不自动重新启用。

用量统计保留。关闭配额时，统计数据库暂时不可用不会阻止模型请求；它是尽力记录的调用尝试计数，不代替供应商账单。鉴权、超时、取消、并发、队列容量、幂等提交和结构化校验继续生效。供应商自己的服务约束由供应商处理。

验证结果：

- 本地及部署暂存环境均通过 124 项服务端测试，新增 8 项覆盖默认无限制、显式 -1、旧额度已耗尽后各接口及后台任务继续可用、用量统计失败、状态返回和安装模板。
- 部署前检查无排队／运行任务；保留历史计数后更新服务。
- 线上进程读回三个配置均为 -1，`/agent/status` 的三个 `usage_limits` 值均为 null，后台任务能力正常。
- 真实合成 Flash 请求在原计数 **100** 的基础上成功完成，计数增加到 **101**。重复提交仍为同一任务，确认取回后结果已清理。没有发送用户健康记录。
- 46 个线上源码／规则文件哈希与当前工作区一致。App 代码和二进制未改动，不重做编译、安装或将本次 API 测试写成新的真机反馈。

先前已经显示额度错误的消息保留其失败状态；点“重试”即可重新提交，不自动重发旧消息。
