# Mateo Fit 0.7.0（12）首页 AI 教练

交付日期：2026-11-03。沿用 `com.personal.xuxu.app` 和 `XuXu/records-v1.json`，覆盖安装，没有卸载 App，也没有读取或导出手机健康原始数据。

## 已交付的使用流程

- **文字对话**：首页直接提问、连续追问；回答呈现训练、配餐、身体趋势和周复盘卡片。顶部模块和原底部页签均可使用，首页表单关闭后回到原对话。
- **选择数据范围**：文字与必要个人摘要分别授权。摘要默认不选；本次会话授权在进入后台或结束对话后失效。仅查看模块不会反复询问。未授权或网络失败时保留输入，本地记录与已有计划仍可用。
- **确认操作**：模型只解释当前事实并选择本地候选。确认当天时间调整会保留实际完成组数、重查计划与快照、重新评估剩余目标。器械替代打开既有训练表单；不会凭模型自由文本直接写计划。周复盘继续使用既有证据门槛和有限调整。
- **餐食**：照片和描述另行逐次授权，不带健康摘要或历史。结果是待确认草稿，包含原图、描述、时间、识别结果及营养来源。进入修改页保留这些内容；改食物、份量或照片清除旧 AI 估计。核对保存后写一条正式记录和实际操作结果，才参与合计。取消、失败和重启不会把草稿算成已吃。
- **恢复**：输入、处理状态、待确认卡片、餐食草稿纳入本地 JSON 与完整备份。未完成请求恢复为可手动重试，不自动重发。最近四轮对话可包含已提交的本地操作结果；历史回复不覆盖最新记录。清空聊天不删除正式日志。

“45 分钟”只调整当天可用时间，不修改长期偏好。不适触发暂停时，旧卡片不能绕过暂停直接采用，需要重新确认当天状态。体重外推沿用已有 7／14 天窗口及记录充分性门槛，分开展示实测、趋势和估计，不承诺结果。

## 数据与实现

新增 `POST /assistant/respond`；兼容原餐食分析、旧路由和旧客户端。请求携带不透明请求/快照 ID、有限历史、授权范围、计划版本和本地聚合事实；每项事实保留时间、单位、来源、修订和质量。未确认档案、缺失记录不伪装成确定数值。原始 HealthKit UUID、样本和包含原始数据的复盘校验串不对外发送。

服务端加载既有教练技能及训练、饮食、复盘规则，校验 JSON Schema、请求与快照匹配、证据 ID 和本地候选白名单。模型没有写入工具。App 确认事件重新核对数据新鲜度、当天状态、禁忌、计划版本与本地规则，并使用幂等键。餐食照片和记录由本地事务提交；延迟到达的编辑更新不能恢复已经提交的草稿。

沿用 HTTPS、设备钥匙串、服务端凭据、并发和每日请求限制。客户端请求超时 45 秒、总资源超时 50 秒；供应商请求超时 35 秒。最多 2 个并行请求、每分钟 10 次、每天 100 次，不自动重试。次数上限不等于费用硬上限。取消会停止本机等待，不能撤回服务商已收到的数据。

私人服务不持久化请求内容；供应商可能保留已提交内容。删除本地记录不删除供应商副本，不能把该实现当作零留存承诺。政策与删除请求路径见 [DeepSeek 隐私政策](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html)。未代用户提交删除请求。
